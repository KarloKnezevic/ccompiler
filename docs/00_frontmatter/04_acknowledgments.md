# Acknowledgments

This project reflects contributions from students, reviewers, and instructors who treated compiler construction not as an abstract exercise but as disciplined engineering. The strongest parts of this system emerged from repeated review cycles that demanded both formal rigor and practical clarity.

Special acknowledgment is due to the maintainers of FRISCjs, whose tooling makes architecture-level experimentation and deterministic educational workflows possible. The project also benefits from open-source tooling ecosystems, including the Java build and testing stack, documentation and diagram generation tools, and reproducible scripting environments.

The pedagogical orientation of this monograph was shaped by recurring classroom and project questions: Why must IR be strictly typed? Why do control-flow details dominate backend correctness? Why do mathematically correct optimizations still break programs when representation invariants are violated? Those questions directly influenced chapter organization and explanatory depth.

Finally, this work acknowledges the value of honest debugging reports from users and testers. Timeout logs, failing examples, edge-case regressions, and ambiguous diagnostics all exposed assumptions that were previously undocumented. Many chapters in this book are stronger specifically because those failures were investigated and converted into explicit design rules.
