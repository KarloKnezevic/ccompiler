# Preface

A compiler project becomes genuinely educational only when its internal contracts are explicit enough that another engineer can reimplement the system from the outside. This book is written under that principle. It does not only document what exists in the repository; it explains why it exists in that form, what assumptions are encoded in each phase boundary, and how those assumptions constrain future changes.

The material is organized to support both top-down and bottom-up study. A reader can begin from formal language and automata theory and proceed to deterministic parsing, typing, and code generation. A different reader can begin from concrete issues in runtime behavior --- simulator timeouts, stack corruption, or unexpected return values --- and trace those issues back to code generation templates, IR semantics, and front-end guarantees. Both routes are valid, and both are intentionally supported by the chapter structure.

This monograph also treats operational quality as part of compiler theory. Theoretical correctness is necessary but insufficient in practice. Reproducibility, diagnostics, failure localization, and maintainability are all modeled as part of the core architecture. As a result, the book includes practical material that many textbooks omit: artifact naming contracts, CLI orchestration policy, phase failure behavior, deterministic optimization ordering, and run-to-run comparability under simulator constraints.

The scope is deliberately ambitious for an educational project. The compiler covers lexing, parsing, semantic analysis, strict typed intermediate representation, seventeen optimization passes, FRISC backend lowering with integer and fixed-point helper routines, and simulator integration with both fast execution and debug instrumentation paths. The implementation is modular and test-driven, and the documentation mirrors that architecture.

Each major theoretical concept introduced in this book has a direct class-level mapping in the Java codebase. The lexer is built from Thompson NFA construction and subset construction to DFA. The parser uses canonical LR(1) tables constructed from a declarative grammar specification. The semantic analyzer dispatches by grammar production to rule families. The IR is defined by a formal BNF grammar in `config/ir_definition.txt`. The optimizer runs a fixed-order pipeline with bounded iteration. The code generator uses template-driven lowering with helper routine emission. These mappings are not incidental; they are the organizing principle of the text.

If this book is used in coursework, a recommended approach is to assign alternating theory and implementation sessions: formal chapter sections first, then source-guided reading and instrumented runs. If used for self-study, the same alternation is advised; understanding grows fastest when each formal definition is immediately verified against a real artifact.
